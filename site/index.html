      Périmètre
      Tous les dépôts de l’organisation, PR créées au cours des 12 derniers mois. La période choisie filtre les PR créées et la date des reviews, commentaires et merges. Les PR et reviews des bots sont exclues.
      PR de code
      Toutes les PR sauf celles de release (release/*, release-please, develop vers master) et de synchronisation de branches (merge*, back-merges, project/…/main vers develop ou master), comptées à part dans « Release / intég. ». Merges, délais, tailles et reviews ne portent que sur les PR de code.
      Type de dépôt
      Déduit des langages détectés par GitHub : Vue donne front ; PHP, Go, Rust donnent back ; Dart (Flutter) donne mobile ; la documentation, l’infrastructure et l’outillage sont classés « autres ». TypeScript et JavaScript comptent en front à côté de Vue, en back sinon. Quelques dépôts sont classés à la main.
      Stack
      Répartition des PR de code (auteurs) ou des PR relues (relecteurs) entre dépôts front, back et mobile, et technologies principales de ces dépôts. Les dépôts « autres » n’y comptent pas. « Full-stack » : au moins 30 % des PR côté back et au moins 30 % côté client (front ou mobile).
      Technologies
      Les langages d’un dépôt sont regroupés sous le framework que déclarent ses fichiers de dépendances (composer.json, package.json, pubspec.yaml) : PHP et Blade sous Laravel, Vue et TypeScript sous Nuxt, Dart sous Flutter, TypeScript sous NestJS… Chaque PR de code est répartie entre les technologies de son dépôt, au prorata de leur part dans le code (moins de 2 % : ignorée). Logos : Simple Icons.
      Mises en production
      PR de release mergées dans master ou main, y compris celles de release-please.
      Part de hotfix
      PR de code dont la branche commence par hotfix, rapportées à toutes les PR de code.
      Taux de merge
      Mergées / (mergées + fermées sans merge).
      Délais et taille
      Médianes, moins sensibles que la moyenne aux quelques très grosses PR. Attente 1re review : de la création à la première review ou au premier commentaire d’une autre personne. Délai de merge : de la création au merge. Taille : lignes ajoutées plus supprimées.
      TMA
      PR de code dont la branche commence par hotfix, créées sur la période. « Part de ses PR » : hotfix de la personne rapportés à toutes ses PR de code.
      Mergées sans review
      PR de code mergées sans aucune review ni commentaire d’une autre personne que l’auteur.
      PR en attente de review
      PR de code ouvertes, hors brouillons, sans aucune review ni commentaire d’une autre personne.
      PR relue
      Au moins une review ou un commentaire de quelqu’un d’autre que l’auteur. Dans l’évolution, elle compte dans la période de la première intervention.
      Commentaires par PR relue
      Commentaires dans le code, commentaires généraux et reviews « commentaire », divisés par les PR relues.
      Approbations sans commentaire
      Parmi les PR approuvées, part de celles où le relecteur n’a laissé aucun commentaire.
      Noms
      Nom du profil GitHub, sinon identifiant.

      Données GitHub actualisées automatiquement en semaine, à intervalles irréguliers. Pour les mettre à jour tout de suite, utilise le bouton ⟳ de la navigation, ou ouvre le workflow Sync and deploy puis clique sur « Run workflow » (accès en écriture au dépôt requis).

      Lancer une synchro complète ?

      Elle recharge depuis GitHub toutes les PR des 12 derniers mois, dépôt par dépôt : environ 10 minutes, pendant lesquelles la page garde les données actuelles.

      À réserver aux données qui semblent fausses ou incomplètes : pour les dernières PR, la synchro rapide suffit.
