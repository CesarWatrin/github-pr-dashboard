    Méthode

    Périmètre
    Tous les dépôts de l’organisation, PR créées au cours des 12 derniers mois. La période choisie filtre les PR créées (auteurs) et la date des actions (reviews, commentaires, merges).
    PR exclues des reviews
    PR de release (release/*, release-please, develop vers master) et de synchronisation de branches (merge*, back-merges, project/…/main vers develop ou master). Elles restent comptées dans les PR ouvertes.
    Bots
    Comptes de type bot (GitHub Apps) et comptes de service, exclus partout.
    PR relue
    La personne a déposé au moins une review (approbation, commentaire ou demande de changements) ou un commentaire sur la PR. Les réponses de l’auteur sur sa propre PR ne comptent pas.
    Commentaires
    Commentaires dans le code, commentaires généraux sur la PR, et reviews « commentaire » sans commentaire dans le code.
    Approbations
    Reviews « Approve ». Une personne qui réapprouve une PR après de nouveaux commits compte plusieurs approbations.
    Comment. / PR
    Commentaires divisés par PR relues.
    Approb. sans comment.
    Parmi les PR approuvées par la personne, part de celles où elle n’a laissé aucun commentaire.
    Fichiers et lignes
    Taille des PR relues : fichiers modifiés et lignes ajoutées plus supprimées. La médiane est moins sensible aux quelques très grosses PR que la moyenne.
    Taux et délai de merge
    PR de code créées sur la période : mergées / (mergées + fermées sans merge), et délai médian entre la création et le merge.
    Noms
    Nom affiché sur le profil GitHub, ou identifiant quand le profil n’a pas de nom.

    Source : API GitHub, PR créées au cours des 12 derniers mois. Données actualisées toutes les 15 minutes, du lundi au vendredi en journée.
